# yxb2018/MoviePilot-Plugins · MoviePilot V3 插件仓库

本仓库包含两个 MoviePilot V3 插件：**下载目录空间清理（DownloadsCleaner）** 与 **PT 媒体库检测（PtLibraryCheck）**。仓库原名 `DownloadsCleaner`，随着插件数量增加已改名为 `MoviePilot-Plugins`（旧地址由 GitHub 自动跳转，raw 地址不会，请使用新地址）。

## 插件一：下载目录空间清理（DownloadsCleaner）

MoviePilot V3 插件：**磁盘可用空间低于阈值时，自动清理下载目录中已入库、做种超时的下载任务**。

## 功能特性

- **空间触发**：监控盘可用空间低于阈值（默认 300 GiB）开始清理，删到目标线（默认 350 GiB）即停
- **待删除列队**：每轮刷新符合条件的种子清单并在详情页展示（做种时长降序），空间不足时才依规则删除
- **清理范围白名单**：仅清理「清理目录」指定子树内的任务（默认 `E:/Downloads`），天然排除 SSD / 保种专区
- **多重防护**（命中任意一条即跳过清理，**全部是保护性质**）：
  - **排除目录**：save_path 命中子树即跳过，**优先于清理目录**（清理目录内想保留的子目录填这里）
  - **保护标签**：默认 `保种`、`H&R`
  - **未入库待确认标签**（默认 `未入库待确认`）：清理范围内「已整理且 MP 有整理记录但结果为失败」的疑似入库失败种子**由插件自动打上**该标签保护；MP 整理记录成功（已入库确认）后**自动移除标签**；带「已整理」但 MP 无任何整理记录的种子不理会
  - **保护关键词**：路径或名称命中即跳过（如 `migration`）
  - **完成保护天数**（默认 7 天）：防止刚入库还在不稳定窗口期被删
  - 分享率门槛 / 小文件保护 / 要求已入库（MP 整理记录成功）
- **候选排序**：按做种时长从长到短清理，单轮数量可设上限
- **两阶段删除（可选）**：第一轮只打「待清理」标签，下一轮才真删，留出人工干预窗口
- **自动识别 MP 设置**：下载器（qBittorrent / Transmission）、通知渠道均从 MoviePilot 系统设置自动读取，无需填写地址密码
- **演练模式**：只记录不删除，先观察日志确认候选符合预期再切正式
- **同步清理 MP 记录**：删除任务同时清理整理记录与下载记录，避免幽灵记录
- **空目录回收（可选）**：删除后回收清理目录子树下的空目录
- **详情页**：累计/本轮删除统计、磁盘状态、当前候选清单、最近删除记录

> ### ⚠️ 名单语义速查（重要，避免配反）
>
> 本插件有多个名字带"名单"的配置，作用方向**不同**，配反了后果严重：
>
> | 配置 | 作用方向 | 命中后的效果 |
> |------|---------|-------------|
> | `clean_dirs`（清理目录） | **删除范围** | 只有目录子树内的任务才会被清理 |
> | `exclude_dirs`（排除目录） | **保护** | 跳过清理（优先于清理目录） |
> | `protect_tags`（保护标签） | **保护** | 跳过清理 |
> | `unconfirmed_tag`（未入库待确认标签） | **保护** | 跳过清理；MP 整理记录成功（已入库确认）后自动移除标签 |
> | `block_keywords`（保护关键词） | **保护** | 跳过清理——**这是保护名单，不是删除名单** |
>
> 记忆口诀：**空间触发的删除里，除了 clean_dirs 其余全是"命中即不删"。**
>
> ### 🏷️ 未入库待确认标签机制（全自动、零维护）
>
> 运行逻辑只有两条，其余交给插件：
>
> 1. **自动打标（保护）**：每轮扫描清理目录内**已完成、带 MP「已整理」标签、且 MP 有整理记录但结果为失败**的种子
>    ——判定为"疑似入库失败"，自动打上 `未入库待确认`（可自定义）并保护，一律不删
> 2. **自动摘标（回归列队）**：带该标签的种子一旦出现 MP 整理记录（status 成功且目标在媒体库路径），
>    插件**自动移除标签**，回归待删除列队
> 3. 仍受保护的种子每轮生成清单快照，在 **WEBUI 顶部（详情页与设置页）和消息通知里持续提示**，
>    直到 qB 中该标签消失为止；提示是纯展示，处不处理都不影响插件运行
> 4. 不再需要填任何 Hash：`verified_extra`（强制删除许可 Hash）已移除——上万个种子人工核对不现实
>
> 原理同 MP「整理成功后自动打『已整理』标签」的反向应用：标签是给人看的，插件负责维护。
> 注意：打标是**条件驱动**的，只要"已整理且整理记录为失败"这个根因还在，手动删掉标签下一轮仍会被打回；
> 想让它可删，请先把入库问题解决（整理记录出现后插件自动放行），或在 qB 移除「已整理」标签。


## 安装

1. 将本仓库加入 MoviePilot 插件市场（`PLUGIN_MARKET` 环境变量，多个仓库逗号分隔）
2. 在 WebUI 插件市场搜索「下载目录空间清理」并安装
3. 进入插件配置，调整阈值/目录/标签等参数，保存

## 配置说明

| 配置 | 默认 | 作用 | 说明 |
|------|------|------|------|
| enabled | 关 | - | 启用插件 |
| dry_run | 开 | - | 演练模式，只记录不删除（**首次使用建议先演练**） |
| onlyonce | 关 | - | 立即运行一次（执行后自动复位） |
| cron | `0 */6 * * *` | - | 检查周期 |
| monitor_path | `E:/` | - | 监控盘目录 |
| threshold_free_gb | 300 | 触发 | 可用空间低于该值开始清理（GiB） |
| target_free_gb | 350 | 停止 | 清理到该可用空间即停（GiB，软目标） |
| downloaders | 空=全部 | - | 下载器多选（自动识别 MP 配置） |
| clean_dirs | `E:/Downloads` | **删除范围** | 清理目录白名单，仅子树内任务会被清理 |
| exclude_dirs | 空 | **保护** | 排除目录，命中子树即跳过，优先于清理目录 |
| protect_tags | `保种`/`H&R` | **保护** | 保护标签，命中即不清理 |
| unconfirmed_tag | `未入库待确认` | **保护** | 未入库待确认标签（本插件唯一管理的标签）：清理范围内「已整理且 MP 整理记录为失败」的种子自动打上该标签；qB 中命中该标签的种子一律不删；MP 整理记录成功（已入库确认）后自动移除；带「已整理」但 MP 无任何整理记录的种子不理会 |
| block_keywords | 空 | **保护** | 保护关键词，路径/名称命中即跳过（不是删除名单） |
| min_seeding_days | 15 | 过滤 | 最小做种天数 |
| protect_recent_days | 7 | 过滤 | 完成保护天数，完成不满该天数不清理 |
| min_ratio | 0 | 过滤 | 分享率门槛（0=关） |
| min_size_gb | 0 | 过滤 | 小文件保护（0=关） |
| require_library | 开 | 过滤 | 要求已入库（MP 整理记录成功）才允许删除；带未入库待确认标签的种子一律不删 |
| delete_files | 开 | 动作 | 同时删除本地文件 |
| delete_history | 开 | 动作 | 同步清理 MP 历史记录 |
| clean_empty_dirs | 关 | 动作 | 空目录回收 |
| tag_then_delete | 关 | 动作 | 两阶段删除 |
| max_delete_per_run | 30 | 动作 | 单轮最多删除任务数 |

## 注意事项

- qBittorrent 删除任务并删文件为**永久删除、不进回收站**，请谨慎开启并先演练
- 每轮都会刷新「待删除列队」（详情页可见），但**只有空间低于阈值才真正删除**
- 「已整理」标签不等于保证入库，删除前以整理记录（status=成功且目标在媒体库路径）为准
- 未入库待确认提示会持续到 qB 中该标签消失；通知为异步发送，渠道不可用也不会卡住清理
- 停止线为软目标：候选不足时可能停在线下
- qB 删除文件为异步落盘，停止线判断时刻的可用空间可能还没算上刚删的文件
- ⚠️ 调高 threshold_free_gb 后请检查 target_free_gb：插件会把它规范化到不低于阈值

## 技术说明

- 插件仅操作下载器与本地磁盘，不访问 115 等网盘
- qB 连接信息全部来自 MoviePilot 下载器配置，插件不存储任何凭据
- V3 SDK：`app.sdk.plugin._PluginBase` / `app.sdk.services.DownloaderHelper` / `app.db.oper.transferhistory`

## 本仓库的另一个插件：PT 媒体库检测（PtLibraryCheck）

给 PT 站点油猴脚本提供查询接口：传入种子标题（或站点已填的 IMDb ID），返回该资源
**是否已在 MP 配置的媒体服务器（Emby / Jellyfin / Plex）里**，以及在库版本的
分辨率 / 杜比视界 / HDR / 编码 / 音轨 / 字幕 / 分集情况。

### 安装

1. 把本仓库加入 MoviePilot 插件市场（`PLUGIN_MARKET` 环境变量，多个仓库逗号分隔）：
   `https://github.com/yxb2018/MoviePilot-Plugins`
2. 在 WebUI 插件市场搜索「PT媒体库检测」并安装
3. 油猴脚本侧：新建脚本粘贴脚本全文 → 菜单「① 设置 MP 地址与 API Key」

### 接口

```http
GET /api/v1/plugin/PtLibraryCheck/check?title=<标题>[&subtitle=<副标题>][&imdb=tt1234567][&season=1][&episode=9]
```

- `imdb` 优先：站点种子行里已填 IMDb 时直接传 `tt号`，识别更准更快；
  Emby/Jellyfin 会用 `AnyProviderIdEquals=imdb.ttXXXX` 直接定条目，Plex 用 imdb 给候选加权
- 只传 `imdb` 不传 `title` 时，Plex 无法按名搜索（会返回明确提示），Emby/Jellyfin 不受影响
- 认证：插件配置里「允许匿名访问查询接口」打开则免密钥，关闭则请求头带 `X-API-KEY`

### 说明

- 复用 MP 已配置的媒体服务器凭据，**插件与油猴脚本都不保存 Emby/Plex 密钥**
- 查询结果按标题+imdb 缓存（默认 24 小时，可在插件配置里改/关）
- 插件代码：`plugins.v3/ptlibrarycheck/`，清单：`package.v3.json`
- 配套油猴脚本：`userscripts/PT媒体库检测.user.js`（脚本内不含任何域名与密钥，
  地址/Key 由油猴菜单录入并只存在 Tampermonkey 存储里），说明见 `userscripts/README.md`
